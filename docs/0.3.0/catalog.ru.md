# Предпросмотр импорта каталога товаров

[EN](catalog.en.md) · [RU](catalog.ru.md) · [Руководство](ru.md) · [Справочник API](reference.ru.md) · [Версии](../index.md) · [README](../../README.md)

Поставщик прислал новый каталог. До применения приложение должно показать,
какие товары появились, исчезли или изменились. model-change-set сопоставляет
текущую и предложенную коллекции по артикулу и возвращает отчёт. Загрузка данных,
запись в БД и решение о допустимости изменений остаются у приложения.

Начните с [ProductCatalogService.java](../../examples/catalog-preview/src/main/java/example/catalog/ProductCatalogService.java).
Вся настройка библиотеки — ключ и два значимых поля.
[Запускаемая программа](../../examples/catalog-preview/src/main/java/example/catalog/CatalogPreview.java)
передаёт этому же сервису данные, вызывает сравнение и проверяет результат.

## Подключить сервис к существующему проекту

Добавьте зависимость Maven или Gradle из [README](../../README.md). Сейчас артефакт
нужно предоставить локально: по этим координатам ещё нет релиза в Central.
Библиотека не имеет зависимостей времени выполнения. Достаточно Java 17;
Spring, веб-фреймворк и драйвер БД для неё не нужны.

Поместите [Product.java](../../examples/catalog-preview/src/main/java/example/catalog/Product.java)
и [ProductCatalogService.java](../../examples/catalog-preview/src/main/java/example/catalog/ProductCatalogService.java)
в src/main/java/example/catalog либо замените Product существующей моделью.
В файлах есть package и все импорты. Создайте сервис один раз и вызывайте
preview(current, incoming) из своего процесса импорта или согласования.
Конфигурационный файл библиотеки, наследование и реализация её интерфейсов не нужны.

Приложение отвечает за согласованное чтение и права доступа. Например, прочитайте
каталог с известным номером версии, покажите отчёт и перед одобренной записью
проверьте, что версия не изменилась. Сам отчёт не защищает от другого процесса,
который успел обновить каталог после сравнения.

## Выбрать только значимые поля

```java
private final ModelDiffer<Product, String> differ = ModelDiffer.keyedBy(Product::sku)
    .field("name", Product::name)
    .field("price", Product::price, FieldEquivalence.decimalValue())
    .build();
```

Это определение из полного сервиса. ModelDiffer и FieldEquivalence находятся в
io.github.alex59.modelchanges. Артикул сопоставляет товары между снимками, имена
выбранных полей подписывают изменения. importedAt не выбран: новое время импорта
само по себе не меняет товар.

| Настройка | Поведение по умолчанию |
| --- | --- |
| Порядок ключей | Естественный возрастающий; Comparable ключа должен согласовываться с equals |
| Равенство полей | Objects.deepEquals: поддерживает null и содержимое прямых значений-массивов, для остальных объектов использует equals |
| Поля | Только выбранные явно; без полей сравнивается лишь состав |
| Повторный/null-ключ или null-модель | Ошибка, без молчаливой замены записи |
| Результат | Неизменяемые контейнеры по порядку ключей; поля идут в порядке объявления |

Построитель хранит изменяемую настройку, его не следует менять из нескольких
потоков. build() фиксирует набор полей: последующие добавления не меняют ранее
созданные объекты сравнения. Готовый ModelDiffer неизменяем и допускает повторное
использование, если методы модели и правила равенства безопасны для совместного
доступа. Модели и значения полей не копируются глубоко. Во время сравнения они
должны быть стабильны; неизменяемые модели упрощают это требование.

## Равенство без повторяющихся проверок null

Каталог использует decimalValue(), поэтому 10.0 и 10.00 равны по числовому значению.
Правило не округляет, не конвертирует валюты и не добавляет допуск погрешности.
Если регистр названия несущественен, выберите это явно:

```java
var names = ModelDiffer.keyedBy(Product::sku)
    .field("name", Product::name, FieldEquivalence.ignoringCase()).build();
```

Notebook и NOTEBOOK равны, а Notebook и " Notebook" — нет. Используется
String.equalsIgnoreCase, без языковой сортировки и нормализации Unicode.
Оба готовых правила считают null равным только null. Отсутствующее значение
отличается от нуля и пустой строки. Отчёт сохраняет исходные значения, не меняя их.

Для собственного правила поручите обработку null библиотеке:

```java
var names = ModelDiffer.keyedBy(Product::sku)
    .field("name", Product::name, FieldEquivalence.nullSafe(
        (String left, String right) -> left.strip().equals(right.strip())))
    .build();
```

Внутреннее правило получает только два ненулевых значения. В отличие от этих
помощников, обычные field(name, getter, predicate) и Field.comparing передают
null в пользовательское правило без изменений, сохраняя прежнее поведение.
Все три варианта проверяет [CatalogPreview.java](../../examples/catalog-preview/src/main/java/example/catalog/CatalogPreview.java).

## Прочитать отчёт перед применением

Текущий снимок содержит P-1, P-2 и P-3, новый — P-1, P-2 и P-4; порядок специально
различается. У P-1 изменились только время импорта и масштаб десятичной дроби.
Цена P-2 выросла с 2.00 до 2.50.

```text
MODIFIED P-2 [price]
REMOVED P-3 []
ADDED P-4 []
added=1; removed=1; modified=1; membership=2; sortedMatches=true
```

Для `report`, полученного из preview:

```java
var additions = report.added();
var removals = report.removed();
var edits = report.modified();
var unchanged = report.isEmpty();
```

Изменённая запись содержит прежнюю/новую модели и список FieldChange с name(),
before(), after(). У добавления нет прежней модели, у удаления — новой. Списки
полей у этих двух видов пусты: появился или исчез весь объект. Смена артикула —
удаление и добавление, а не автоматически распознанное переименование.

Передайте отчёт экрану согласования или механизму аудита. Библиотека не применяет
его и не доказывает безопасность соответствующей миграции или обновления.
Наличие значения в отчёте не означает, что его можно писать в журнал без проверки
на чувствительные данные.

## Состав и свой порядок

Когда важен только набор товаров:

```java
var membership = ModelDiffer.keyedBy(Product::sku).build();
```

В примере останутся удаление P-3 и добавление P-4, изменение цены P-2 исчезнет из
отчёта. Собственный порядок использует тот же построитель и алгоритм:

```java
var reverse = ModelDiffer.keyedBy(Product::sku, java.util.Comparator.reverseOrder())
    .field("name", Product::name).build();
```

Равенство ключей должно быть стабильным, а полный порядок — согласованным с equals.
Сравнение ключей без учёта регистра при регистрозависимом equals может создать
неоднозначность: неравные ключи в одной позиции будут отклонены. Правила равенства
бизнес-полей не следует подменять правилами идентичности ключей.

## Большие отсортированные источники

Для обычных конечных коллекций используйте compare: он индексирует оба снимка
и возвращает весь отчёт. То же определение поддерживает compareSorted для двух
итераторов, уже строго возрастающих в выбранном порядке ключей. Этот режим
не строит два индекса и синхронно передаёт по одному изменению.

```java
var emitted = new java.util.ArrayList<io.github.alex59.modelchanges.Change<Product, String>>();
differ.compareSorted(sortedCurrent, sortedIncoming, emitted::add);
```

Здесь ожидаются два отсортированных Iterator<Product>. Полный
[пример](../../examples/catalog-preview/src/main/java/example/catalog/CatalogPreview.java)
сортирует маленький набор только для демонстрации и проверяет совпадение
результатов. Для больших данных получайте отсортированные курсоры из источника:
сортировка всех снимков в памяти сводит на нет выигрыш этого режима. Курсоры
закрывает вызывающее приложение.

Проверка идёт постепенно. Поздний повторный ключ, нарушение порядка или исключение
обработчика могут возникнуть после выдачи части изменений; транзакции вокруг
обработчика нет. Если частичное применение недопустимо, приложение должно сначала
подготовить результат либо использовать подходящую транзакционную границу.
Фоновых задач, асинхронной отмены и автоматического закрытия ресурсов здесь нет.

## Разобраться с ошибкой данных или правила

- Duplicate key: исправьте источник; библиотека не выбирает победителя среди дублей.
- Null model/key: передайте модель со стабильным идентификатором; null в отдельных полях допустим.
- Duplicate field name: уберите повторное имя до build().
- Cannot compare field: посмотрите исходную причину — ошибка чтения поля или пользовательского сравнения. Сообщение называет ключ и поле.
- Лишние изменения: проверьте выбранные поля и равенство. Обычное сравнение учитывает масштаб BigDecimal; decimalValue() подключается явно.
- Отчёт устарел: перед записью повторно прочитайте или проверьте версию исходных данных.
